# Startup Waiting and Signal Duration

These additions support the November 10 manuscript entitled **Modeling Data Center Demand Response in Power Systems With Task Execution and Delayed Cost Feedback**. They supplement the existing joint-system results rather than replace them.

## Included data and manuscript mapping

| Location under `supplemental/` | Contents and use |
| --- | --- |
| `response_replay_20261110/results/` | Nine paired cases, 27 representation rows, interval-energy arrays and reconstruction audits; Appendix III.6 |
| `signal_duration_20261110/results/` | Nine date/seed bundles, three signal durations, three representations, 81 metric rows; main Table V and Appendix III.7 |
| `signal_duration_20261110/existing_analysis/` | Normalization and dispatch analyses of existing runs supporting the electrical interpretation |

The dates are July 27, August 5 and August 21, 2020; controller seeds are 17, 29 and 43. All combinations are retained. Seed ranges describe controller variability, not independent real-world deployments.

The three representations are R (recorded task starts), C (resource waiting omitted while release constraints remain), and A (release waiting also omitted). Assignment times and destinations are held fixed within each replay. These are offline timing ablations, not new scheduling policies or prospective predictors. Power profiles and task durations come from PM100; site deployments and sequential dependencies are constructed inputs.

Arrays `off_R`, `on_R`, `off_C`, `on_C`, `off_A`, and `on_A` contain interval energy in MWh, indexed by five-minute interval and site. Positive signal-on minus signal-off differences mean increased demand. Summary columns explicitly distinguish kWh, kW, percentage points and minutes. Generation cost is distinct from the computing operator's electricity charge.

## Recheck the bundled results

From the repository root, after installing `requirements.txt`:

```sh
python -m unittest discover -s supplemental/response_replay_20261110 -p 'test_*.py'
python -m unittest discover -s supplemental/signal_duration_20261110 -p 'test_*.py'
python supplemental/signal_duration_20261110/summarize_duration.py --results supplemental/signal_duration_20261110/results
python supplemental/signal_duration_20261110/make_duration_tables.py
```

The summary command recomputes summaries from all returned arrays and checks energy, service and seed coverage. Table generation writes to `supplemental/signal_duration_20261110/table_exports/`; it does not modify a manuscript. The original server runs are preserved results, not newly rerun experiments during this repository update.

## Full reproduction with external inputs

Obtain the raw inputs as described in [DATA.md](DATA.md). Use `systems/main/study_manifest.json` to select the nine `primary` bundles whose names include `_stagger_`; their indices are 001, 003, 005, 012, 014, 016, 023, 025 and 027. Run each frozen protocol with `systems/main/run.py`, storing its outputs as `runs/main/INDEX` (including `reported`, `reported_pulse`, and `fixed`). Then run:

```sh
python supplemental/response_replay_20261110/replay.py --source runs/main --code systems/main --raw data/raw --out runs/startup_replay
python supplemental/signal_duration_20261110/execute.py --root runs/duration --code systems/main --source runs/main --raw data/raw --old_replay runs/startup_replay --task 0
```

Repeat the duration command with `--task 1` through `--task 8`. Its outputs are in `runs/duration/runs/INDEX`. Summarize that directory with `summarize_duration.py --results runs/duration/runs`. Use empty output locations; existing bundles are intentionally not overwritten. The driver adds 18 closed-loop 1/4-hour runs and one exact two-hour reproduction check, reusing the original two-hour and no-signal runs.

Large raw inputs and full task/decision logs are not distributed here. The compact arrays, per-seed results, audits and CSV summaries included here are sufficient to recheck the reported supplemental aggregates without those logs. Full rerunning requires the external inputs and regenerating the main-study logs.

**Description:** Research code, derived experimental results, interval traces, and reproduction instructions accompanying the manuscript. The study uses externally published PM100 task and power records and RTS-GMLC network data, linked separately in DATA.md.
